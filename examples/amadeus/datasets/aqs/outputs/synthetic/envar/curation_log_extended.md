# Coverage log — AQS, 5 NAAQS criteria pollutants

Supplements `curation_log.md` (full narrative for PM2.5 — read that first
for the shared spatial/temporal/source/license sourcing, identical across
all 5). This file covers the other 4, generated by
`curator/generate_aqs_variants.py`.

## Scope: this is a deliberate expansion, not amadeus's own boundary

Earlier in this project, AQS was intentionally scoped to PM2.5 only
("Keep PM2.5 only, not expanding this one"). That decision has been
reversed — the 4 additional NAAQS criteria pollutants below were added on
request. amadeus's `download_aqs()` accepts an arbitrary EPA
`parameter_code`, so it does not bound this the way it bounds PRISM's 7
variables; this 5-pollutant set (the "criteria gases" plus both
particulate matter sizes) is a chosen, complete NAAQS-criteria subset —
not the full AQS parameter table (which also includes lead, individual
VOCs, meteorological parameters recorded at monitor sites, and more).

**Not included**: Ozone (44201) and Lead (14129/85129) — the other two
NAAQS criteria pollutants. Left out only because the original ask named
PM10/CO/NO2/SO2 specifically; adding either is the same generator-table
pattern as everything below (see the main `README.md`).

## Sourcing notes specific to the 4 new pollutants

- **Parameter codes and averaging conventions** — looked-up: EPA's own
  AQS training materials ("AQS Concepts" and "AQS Basics" briefing decks;
  the EPA Criteria Air Pollutants methods document), not recalled from
  memory. These confirm the exact codes and — critically — that CO/NO2/SO2
  are reported to AQS's *daily summary* files as the **daily maximum of a
  shorter sub-daily averaging window** (CO: max of 8-hour running means;
  NO2/SO2: max of 1-hour values), unlike PM2.5/PM10's straightforward
  24-hour mean.
- **`temporal_aggregation_method: maximum` for CO/NO2/SO2 is an
  approximation**, flagged explicitly: the schema's single-enum slot has
  no way to express "maximum of sub-daily means" as one value distinct
  from "instantaneous daily maximum." `maximum` is the closest available
  value (the daily figure genuinely is a max), but the two-stage nature
  of the aggregation is real information this slot alone cannot carry —
  worth raising as a `known-issues.md` candidate if it becomes load-bearing
  for anyone doing sub-daily-sensitive analysis.
- **Units `ppm`/`ppb`** are used for readability, not strict UCUM
  canonical syntax (which represents dimensionless ratios as `10*-6` /
  `10*-9`). The schema's `units_ucum` slot is free text (no enum/format
  validation), so this passes validation, but it is a simplification —
  flagged rather than silently presented as canonically correct UCUM.
- **`concept_status: gap`, `source_license_spdx: public-domain-us-gov`,
  extraction/spatial/day-boundary facts** — all inherited unchanged from
  the already-cited PM2.5 sidecar (same monitor network, same run) — see
  `curation_log.md` for those citations.
- **`source_dataset_name`** is the one field the generator deliberately
  does NOT inherit verbatim — each pollutant gets its own name reflecting
  its parameter code, rather than all 4 silently claiming to be "PM2.5."

## Still not modeled

The real EPA daily summary files carry additional per-pollutant fields
this exercise doesn't touch: AQI category, exceptional-events flags,
method/monitor-type detail, and (for CO/NO2/SO2) the specific hour the
daily max occurred. None of these were fabricated.
