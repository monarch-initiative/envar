# Coverage log — NARR, 30 curated monolevel variables

Supplements `curation_log.md` (full narrative detail for `rhum`/`wind_speed`
— read that first for the shared spatial/temporal/source/license sourcing,
identical across all 30). This file covers the other 28, generated by
`curator/generate_narr_variants.py`.

## Scope: what "coverage" means for NARR, and what's excluded

Unlike PRISM, amadeus does **not** bound NARR to a fixed variable list —
`download_data("narr", variable = <any NOAA short name>)` is a
pass-through. NOAA PSL's monolevel catalog
(`psl.noaa.gov/data/gridded/data.narr.monolevel.html`) lists ~45 short
names. This batch curates a **comprehensive subset of ~30**, deliberately
excluding:

| Excluded | Why |
|---|---|
| `rcq`, `rcs`, `rcsol`, `rct` | Radar/satellite composite QC fields — undocumented beyond their short codes on the public page; could not responsibly assign a `standard_name`/units without fabricating meaning |
| `bmixl.hl1`, `mconv.hl1`, `pottmp.hl1` | Hybrid-model-level-1 boundary-layer research fields — no standard health-exposure use, and the `.hl1` naming needs domain expertise to interpret correctly |
| `hlcy` (storm-relative helicity), `lftx4` (lifted index), `cape`/`cin` retained but severe-weather-specific fields like `hlcy`/`lftx4` dropped | Severe-weather/tornado-forecasting fields, not exposure-relevant |
| `cdcon`, `cdlyr` (convective/non-convective cloud sub-layers), `mcdc`/`hcdc`/`lcdc` (mid/high/low cloud) | Redundant with the retained `tcdc` (total cloud cover) for exposure purposes |
| `mslet`, `pres.tropo` | Redundant with retained `pres.sfc` for a surface-exposure use case |
| `pottmp.sfc` | Potential temperature is a derived meteorological quantity rarely used directly as a health exposure |
| `mstav`, `cnwat`, `bgrun`, `ssrun`, `snom`, `snohf`, `acpcp` | Land-surface/hydrology fields with low direct health-exposure relevance and/or redundant with retained fields (`apcp` covers total precip; `acpcp` is its convective-only subset) |

This is a judgment call, not amadeus's own boundary — flagged as such
(see `curator/known-issues.md` if this needs revisiting).

## Sourcing methodology (applies to all 28)

- **Short names** confirmed against NOAA PSL's own monolevel catalog page
  (`psl.noaa.gov/data/gridded/data.narr.monolevel.html`), not recalled
  from memory alone.
- **CF standard names** used where CF Conventions defines one for the
  quantity (most radiation/flux/humidity/pressure variables have direct
  CF matches); `ENVAR:` minted only for the handful with no CF
  equivalent (snow water equivalent, categorical precip-type flags,
  convective inhibition, total evaporation), following the same
  convention the schema already uses for Heat Index/WBGT.
- **Aggregation method** defaulted to `mean` for continuous fields and
  `sum` for accumulating fields (precipitation, evaporation) — a
  reasonable convention, **not independently confirmed against amadeus's
  actual 3-hourly-to-daily aggregation behavior for each specific
  variable** (same caveat already logged for `rhum`/`wind_speed` in
  `curation_log.md` — verify against a real run).
- **Value ranges** are fixture-generation/sanity bounds chosen for
  physical plausibility in the Phoenix/Tucson July scenario, not
  independently sourced climatological extremes per variable.
- **Spatial/temporal/source/license facts are inherited unchanged** from
  the already-cited `rhum` sidecar (same NARR product, same run) — see
  `curation_log.md` for those citations; they are not re-derived per
  variable.
