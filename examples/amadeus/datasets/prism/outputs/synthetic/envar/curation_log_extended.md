detail — read that first for the shared spatial/temporal/source/license
sourcing, which is identical for all 7). This file covers the other 6,

base plus the per-variable deltas below.

(confirmed from CRAN `amadeus.pdf`: `"ppt"`, `"tmean"`, `"tmin"`,
`"tmax"`, `"tdmean"`, `"vpdmin"`, `"vpdmax"`) — this is amadeus's real,
bounded PRISM coverage, not a chosen subset the way NARR's list is.

## Sourcing notes specific to the 6 new variables

- **Units** (`Cel` for the four temperature variables, `mm` for `ppt`,
  `hPa` for the two VPD variables) — looked-up:
  `prism.oregonstate.edu/documents/PRISM_datasets.pdf`, "Units and
  scaling: tmin, tmax, tmean, tdmean (deg C); ppt (mm); vpdmin, vpdmax
  (hPa)." Same citation covers all 6 at once.
- **`standard_name: ENVAR:vapor_pressure_deficit`** for `vpdmin`/`vpdmax`
  — CF Conventions has no standard name for vapor pressure deficit as
  such (the closest CF terms describe saturation deficit in different
  framings that don't match VPD's exact definition); minted per the
  schema's own established convention for non-CF health-relevant
  quantities (the same pattern used for Heat Index/WBGT elsewhere in the
  schema). Because `standard_name` isn't `CF:`-prefixed for these two,
  `cf_cell_methods` is correctly **omitted** (it's conditionally-core on
  the `CF:` prefix per SPEC.md rule 5 — confirmed by the validator
  itself: these two sidecars show `Core 32/32` rather than `33/33`,
  because `cf_cell_methods` correctly drops out of the Core slot count
  when not applicable, not because something is missing).
- **`concept_mappings`**: only `tmax`/`tmin`/`tmean`/`ppt` get
  `ECTO:0000012` (temperature/precipitation exposure) — `tdmean` and the
  VPD variables were left without a cross-reference rather than reusing
  the same ECTO term speculatively.
- **Value ranges**: chosen per-variable physical plausibility bounds
  (e.g. `ppt` 0-500mm, VPD 0-100/120 hPa) — schema convention (sanity
  bounds, not hard validation), not independently re-verified against a
  climatological extremes reference for each variable.

## Companion data

All 7 variables now live in one wide companion file,
`outputs/prism_all_vars.csv` (24 rows × 7 value columns + identity
columns), from a single extraction run — the fixture generator
(`fixtures/generate_fixtures.py`) produces internally-consistent
synthetic values (`tmin < tmean < tmax`; dewpoint and VPD respond
inversely to a synthetic monsoon-onset event) rather than independent
random numbers per column, so the demo data at least *looks* like one
coherent weather sequence even though it isn't real PRISM output.
